# One Path Study 基幹運営アプリ

集団指導形式の大学受験塾「One Path Study」向けの基幹運営システムです。
生徒名簿・クラス編成/授業スケジュール・出欠管理・演習/要約提出トラッキング・
月次面談記録・社内タスク/相談機能の MVP 6機能（提案書 3-1〜3-6）を実装して
います。詳細な仕様は提案書を参照してください。

## 技術スタック

- Next.js (App Router / TypeScript) + Tailwind CSS v4
- Prisma ORM + PostgreSQL
- NextAuth (Auth.js) v5 Credentials Provider による社員番号＋パスワード認証

## セットアップ（ローカル開発）

Postgres が必要です。ローカルに無ければ Docker で立てるのが手軽です。

```bash
docker run -d -p 5432:5432 \
  -e POSTGRES_USER=app -e POSTGRES_PASSWORD=app -e POSTGRES_DB=onepathstudy \
  postgres:16

npm install
cp .env.example .env   # NEXTAUTH_SECRET を発行して設定してください
npx prisma migrate dev # DBマイグレーションを適用
npm run dev
```

（`npm run dev` はシードを自動実行しません。初回だけ `npm run db:seed` を
実行してください。`npm run build` はマイグレーション適用とシードを自動で
行います＝本番デプロイ時に手動操作は不要です。）

`http://localhost:3000` を開き、以下のシードアカウント（社員番号でログイン）
で入れます。初期パスワードは全員共通で `onepath` で、初回ログイン時に
パスワード変更が必須です（変更が完了するまで他の画面には進めません）。

| 木村朝陽 | 026002 | 役員 |

新しい社員の追加・役職変更・パスワードリセットは、役員アカウントで

## 環境変数

`.env.example` を参照してください。`NEXTAUTH_URL` は意図的に設定していません
（`auth.config.ts` で `trustHost: true` を指定し、リクエスト先のホストから
自動判定します）。これにより Vercel のプレビューデプロイ等、実行時に
ドメインが変わる環境でもそのまま動作します。固定ドメインに限定したい場合の
み `NEXTAUTH_URL` を設定してください。

## Vercel へのデプロイ手順

1. [vercel.com](https://vercel.com) にアクセスし、GitHub アカウントでログイン。
2. 「Add New...」→「Project」→ この `onepathstudy` リポジトリを Import。
   （リポジトリはブランチが1本のみなので、そのままで問題ありません）
3. データベースを用意する：プロジェクト作成画面または作成後の
   「Storage」タブから「Create Database」→ Postgres を選択して接続
   （Neon 等のマーケットプレイス経由になる場合があります。名前は何でも
   構いません）。作成すると接続文字列が発行されます。
4. 「Settings」→「Environment Variables」で以下を設定：
   - `DATABASE_URL`：手順3で発行された接続文字列をそのまま貼り付け
     （Vercel の Postgres 連携が `POSTGRES_URL` 等の別名で変数を追加する
     場合は、値をコピーして `DATABASE_URL` という名前で追加してください）
   - `NEXTAUTH_SECRET`：ランダムな文字列（下記コマンドで生成できます）
     ```bash
     node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
     ```
5. 「Deploy」を押す。ビルド時に `npm run build` が自動実行され、
   マイグレーション適用・初期社員アカウント投入まで自動で完了します。
6. デプロイ完了後に発行される URL（例: `onepathstudy.vercel.app`）を
   梅本さん・木村さん・宮坂さんで共有してください。社員番号（026001/
   026002/026003）と初期パスワード「onepath」でログインできます。

以降、このブランチに新しいコミットを push するたびに Vercel が自動で
再デプロイします。

## メール通知（任意）

タスクを割り当てたとき／相談・クレームを投稿したとき、担当者にメール通知
を送れます（[Resend](https://resend.com) を利用）。設定しなくてもアプリ
自体は問題なく動作します（通知だけスキップされます）。

1. [resend.com](https://resend.com) で無料アカウントを作成し、API キーを発行
2. Vercel の「Environment Variables」に `RESEND_API_KEY` としてそのキーを追加
3. 各社員のメールアドレスを `/settings` の編集画面から登録
4. 再デプロイ（新しいコミットを push するか、Redeploy）

独自ドメイン（例: `onepathstudy.com`）をResendで認証すれば、送信元アドレス
を `RESEND_FROM_EMAIL` で好きなものに変更できます。未設定の間は
`onboarding@resend.dev` から送信されます。

## 役職別アクセス範囲（提案書 3-7）

`lib/permissions.ts` に集約しています。

| 役職 | 範囲 |
|---|---|
| 講師 (TEACHER) | 自分が担当するクラスの出欠・演習提出のみ。生徒名簿・設定は非表示。個人宛タスクは自分が依頼人・担当者のもののみ閲覧可。相談は自分が投稿者・担当者のもののみ閲覧可 |
| 校舎スタッフ (STAFF) | 所属校舎の生徒名簿・クラス・出欠・演習提出。タスクは講師と同様に自分が依頼人・担当者のもののみ。相談は自分の関与分のみ |
| 本部社員 (HQ) | 全校舎の生徒・クラス・出欠・演習提出・相談を横断閲覧（設定は不可）。個人宛タスクは自分が依頼人・担当者のものだけ表示（他の役職と同じ） |
| 役員 (EXECUTIVE) | 本部社員の範囲に加え、社員・役職・校舎・科目マスタの管理（`/settings`）、相談ステータスの管理者権限。個人宛タスクは自分が依頼人・担当者のものだけ表示（他の役職と同じ） |

個人宛タスクは、関係のない人にまで表示されると件数が多く見づらいため、役職に関わらず
「自分が依頼人 or 担当者」のタスクのみが一覧・ダッシュボードに表示されます
（相談・クレームは引き続き本部社員・役員が全件を横断閲覧できます）。

## 個人宛タスク：完了・編集・削除

- タスクのステータスを「完了」にすると、タスク一覧の「個人宛タスク」タブから消え、
  「完了済み」タブに移動します（削除はされません）。
- 作成したタスクは、依頼人（作成者）本人のみが「編集」から内容・担当者・期限・
  タイムテーブル配置を変更できます。担当者側は編集できず、ステータス変更のみ可能です。
- タスクの削除も依頼人（作成者）本人のみ可能です（確認ダイアログあり、取り消せません）。
  「編集」リンクの隣に表示される「削除」から行います。

## 本日のタイムテーブル（ダッシュボード）

ダッシュボードのホーム画面は、当日出勤予定の社員とその時間帯を一覧表示する
「本日のタイムテーブル」のみで構成しています（個人宛タスク・相談等の一覧は
`/tasks` に集約し、ダッシュボードはタイムテーブルに専念させています）。

同じ社員の欄の中で時間が重なる項目（出勤・クラス・スケジュール・カレンダー予定・
タスク）がある場合は、自動的に段（tier）を分けて重ならないように表示します
（区間グラフの貪欲彩色アルゴリズム）。時間が重ならない項目同士は同じ段にまとめて
表示されるため、コンパクトに収まります。

- 表示される時間帯は2種類です：①役員が `/settings` の各社員「シフト」から
  登録した曜日固定の出勤時間、②講師が担当するクラスの授業時間（クラス一覧の
  データから自動反映）。
- 各社員の欄にある「+ タスクを貼る」リンクから、その人・その日・その時間枠を
  あらかじめ入力した状態でタスク登録画面を開けます（タスク作成時に「タイムテーブル
  に配置する日」「開始・終了時刻」を指定すると、その社員の欄にタスクが表示されます）。
  この日時指定は任意項目で、指定しなければ従来通りタスク一覧にのみ表示されます。
- タイムテーブルに貼られたタスクも、個人宛タスクの表示ルールと同様に
  「自分が依頼人 or 担当者」のものだけが見えます。

社員の出勤シフトは `/settings` の社員一覧から「シフト」リンクで登録します
（役員のみ操作可能）。曜日ごとに開始・終了時刻を入力し、空欄の曜日は休みとして
扱われます。日付単位の個別変更・臨時休暇には対応していません（曜日固定のみ）。

タイムテーブルは「本日」だけでなく、上部の「← 前日 / 翌日 →」リンクや日付欄から
任意の日に切り替えて表示できます（URLの `?date=YYYY-MM-DD` で直接指定も可能）。
クラスや出勤シフトは曜日固定の繰り返しなので、選んだ日の曜日に基づいて表示します。

## スケジュール（タスクとは別の予定登録）

「対応が必要なタスク」とは別に、単に時間をブロックするだけの予定（会議・出張・
来客対応など）を登録できます。ダッシュボードの「スケジュールを登録する」ボタン、
またはタイムテーブルの各社員の欄にある「＋予定」リンクから登録します。

- タスクと違い、ステータス（未対応/対応中/完了）はありません。タイトル・対象者・
  日付・開始終了時刻・任意のメモだけを持つ単純な予定です。
- タイムテーブル上は紫色のブロックとして表示されます（出勤=紺、クラス=紺、
  Googleカレンダー=緑、タスク=コーラル、スケジュール=紫、で色分け）。
- Task と異なり、依頼人・担当者以外にも見えます（出勤シフトやクラスと同じ扱いの
  組織内共有情報という位置づけのため）。
- 登録者本人または対象者本人は、タイムテーブル上のブロックをクリックすると
  削除できます（確認ダイアログあり）。それ以外の人には削除ボタンは表示されません。

## Googleカレンダー連携（任意・簡易版）

各自のGoogleカレンダーの予定を、ダッシュボードの本日のタイムテーブルに表示できます。

1. Googleカレンダーの設定画面 →（連携したいカレンダーを選択）→
   「カレンダーの統合」→「非公開URL」（ics形式）をコピー
2. アプリの「個人設定」（ナビゲーションバーの右端、全社員が使えます）を開き、
   コピーしたURLを貼り付けて保存する（保存時に実際に取得できるか確認します）
3. 本日の予定が、自分のタイムテーブルの行に緑色のブロックとして表示されます

- 読み取り専用・一方向（Google→アプリのみ）です。アプリ側からGoogleカレンダーへの
  書き込みはできません。
- Googleカレンダーの非公開URLの更新間隔に依存するため、Google側に予定を登録して
  からアプリに反映されるまで数十分〜数時間かかることがあります（リアルタイムでは
  ありません）。
- 終日予定はタイムテーブル（時間軸表示）の対象外のため表示されません。
- URLの取得に失敗した場合、既にシフト等でタイムテーブルに行がある人はその行に
  「連携エラー」と表示され、行が無い人（シフト未登録）はタイムテーブル下部に
  まとめて注意書きが表示されます（本人が「個人設定」でURLを確認してください）。
- 反映処理はダッシュボードを開くたびにサーバー側でその都度取得する方式です
  （バックグラウンドジョブは使っていません）。カレンダー取得に時間がかかる場合、
  ダッシュボードの表示が多少遅くなることがあります。

## 引き継ぎメモ（生徒詳細ページ）

各生徒の詳細ページ（`/students/[id]`）に、月次面談記録より軽い「引き継ぎメモ」を
用意しています。日々のちょっとした申し送り（「次回は宿題の確認を」等）を投稿でき、
新しい順に一覧表示されます。編集・削除機能はなく投稿のみです。閲覧・投稿できる
役職は生徒名簿へのアクセス権限（3-7）と同じで、講師は利用できません。

## 一斉連絡（保護者へのメール一斉送信）

休講連絡など、生徒の保護者へメールを一斉送信できます（`/announcements`、講師以外が
利用可能）。件名・本文を入力し、任意で「校舎」または「クラス」を指定して対象を
絞り込めます（クラス指定時は校舎の指定より優先されます／校舎スタッフは自分の
校舎の範囲に固定されます）。送信は既存のメール通知の仕組み（Resend、未設定なら
スキップ）を利用します。

- `Student.parentContact` は電話番号などメールアドレス以外の場合もある自由記述の
  ため、メール形式に見える宛先にのみ送信します。宛先形式の妥当性チェックは
  行わないため、無効なメールアドレスでも一見メール形式であれば送信を試みます。
- 送信するとその場で確認ダイアログが出ます（取り消せない操作のため）。
- 送信履歴は `/announcements` で確認できます（件名・宛先・送信件数・送れなかった
  件数）。

## ディレクトリ構成の要点

- `app/(app)/` … ログイン後の画面（ダッシュボード・タスク/相談・生徒名簿・
  クラス・出欠・演習提出・面談記録・設定）
- `app/actions/` … 各機能の Server Actions（フォーム送信の処理）
- `auth.ts` / `auth.config.ts` / `proxy.ts` … 認証とルート保護
  （Next.js 16 では `middleware.ts` が `proxy.ts` に名称変更されています）

- `prisma/schema.prisma` … データモデル定義（前提や判断の根拠はファイル内コメント参照）

## 設計判断メモ（提案書に明記のない項目）

ユーザーへの確認を経て以下の方針で実装しています。

- 個人宛タスクのステータスは「未対応 / 対応中 / 完了」の3段階。
- 相談・クレームに返信スレッド機能は設けず、投稿とステータス変更のみ。
- 相談・クレームは生徒への任意紐付けが可能（生徒名簿と連携、必須ではない）。
- 校舎（キャンパス）は最初から複数校舎に対応するデータ構造を用意（`Campus` モデル）。
- 業務効率化のため、タスク・相談の担当者へのメール通知機能を追加（`User.email`、`lib/email.ts`）。
- 個人宛タスクは、本部社員・役員であっても自分が依頼人・担当者のものしか一覧に出さない（関係者以外に見せると件数過多でわかりにくいため）。相談・クレームは従来通り本部社員・役員が全件横断閲覧できる。
- タスク完了時に一覧から消して「完了済み」フォルダ（タブ）に移動する仕様を追加（削除ではなく非表示化）。
- タスクの編集権限は依頼人（作成者）本人のみとした（担当者側の内容改変を防ぐため）。
- `WorkShift`（曜日固定の出勤シフト）とダッシュボードの「本日のタイムテーブル」、Task.scheduledDate/slotStart/slotEnd（タイムテーブルへのタスク配置用）を追加。出勤予定は曜日固定パターンのみとし、日付ごとの個別変更・休暇申請機能は範囲外とした（ユーザー確認済み）。
- Googleカレンダー連携は、OAuth連携ではなく「各自のICS非公開URLを登録し、アプリが都度取得する」簡易版とした（ユーザー確認済み）。読み取り専用・一方向・準リアルタイム（Google側の更新間隔に依存）という制約があるが、Google Cloud側の事前登録が不要で導入が容易なため。`User.googleCalendarIcsUrl`、`lib/googleCalendar.ts`、`/profile`（個人設定）。
- ダッシュボードのタイムテーブルは「本日」固定ではなく、`?date=` パラメータで任意の日付を表示できるように拡張した（ユーザー確認済み）。
- `HandoverNote`（生徒の引き継ぎメモ）を追加（ユーザー確認済み）。月次面談記録より軽量な日々の申し送り用で、生徒名簿へのアクセス権限をそのまま流用し、編集・削除は設けず投稿のみとした。
- `Announcement`（一斉連絡）を追加（ユーザー確認済み）。`Student.parentContact` の形式（メールか電話番号か）は保証されないため、メール形式に見える宛先にのみ送信し、送れなかった件数を記録する方針とした。宛先形式のバリデーションは行わない。
- `Schedule`（タスクとは別の予定）を追加（ユーザー確認済み）。ステータス管理を持つ「タスク」と、単に時間をブロックするだけの「予定」は概念が異なると判断し、別モデルとした。WorkShift・Classと同様に組織内共有情報として扱い、Taskのような依頼人・担当者限定の可視性制限は設けていない。
- ダッシュボードは、個人宛タスク・相談等の一覧表示をやめてタイムテーブルのみの構成に簡素化した（ユーザー確認済み）。それらの情報は `/tasks` で確認できる。
- タイムテーブルで時間が重なる項目は、固定の2段構成ではなく区間グラフの貪欲彩色アルゴリズムで動的に段数を決めるようにした（ユーザー確認済み）。重ならない項目は同じ段にまとめることでコンパクトに保っている。
- タイムテーブルをさらに拡大し（1時間あたり140px）、各ブロックの幅を実際の時間幅ちょうどに固定した（ユーザー確認済み）。従来は文字数に応じて時間幅より横に広がることがあったが、幅を時間軸と一致させ、収まらないタイトルは2行までの折り返し＋省略（`line-clamp-2`）で対応する方式に変更した。

その他、提案書に記載のない実装判断は `prisma/schema.prisma` 冒頭のコメントに
まとめています（例: `ClassSession` の追加理由、生徒の在籍ステータス追加など）。
